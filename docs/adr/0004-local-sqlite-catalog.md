# ADR-0004: ローカル SSD 上の SQLite WAL カタログ採用と NAS 直接共有の禁止

- Status: Accepted
- Date: 2026-11-25

## 背景
数十万〜数百万ファイルの検索・統計・オフライン閲覧を高速に行うためのカタログ DB 構成を決める必要がある。複数ホスト（Windows PC / macOS / NAS）での利用も見据えている。

## 決定
検索用カタログ DB として **各ホストのローカル SSD 上に配置する SQLite（WAL モード）** を採用し、永続縮小サムネイルもローカル SSD に保持する。**SQLite WAL DB を NAS（SMB/NFS）上に置いて複数ホストから直接開く方式は採用しない**。

## 代替案
1. **NAS 上の SQLite ファイルを複数ホストから共有**: ネットワークファイルシステム上のロック不整合・WAL 破損リスクが高く、ランダムアクセス性能も大幅に劣化する。
2. **PostgreSQL 等の常駐 RDBMS / 分散 DB**: 個人開発のローカル写真管理に対して構築・保守コストが過大。

## 理由
- ローカル NVMe SSD 上の SQLite WAL は単一ホストでの読み書き性能・耐障害性・運用容易性のバランスが最も良い。
- NAS がオフラインのときでも、ローカルのカタログとサムネイルで検索・閲覧を継続できる。

## 影響
- マルチホスト間の情報共有は DB ファイル直接共有ではなく、カタログのエクスポート / インポート（将来は必要に応じ同期プロトコル）で行う。
