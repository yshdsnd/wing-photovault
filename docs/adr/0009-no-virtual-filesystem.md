# ADR-0009: 仮想ファイルシステム（WinFsp / Dokan 等）を当面採用しない

- Status: Accepted
- Date: 2026-11-25

## 背景
Lightroom Classic などの外部アプリ連携において、SSD→HDD への階層移動による物理パス変化を隠蔽する手段として、WinFsp / Dokan 等による仮想ドライブ（仮想ファイルシステム）を提供する案が考えられる。

## 決定
WinFsp / Dokan 等による仮想ファイルシステムは **当面採用しない**。外部アプリへは現在の物理パスをそのまま引き渡し、Lightroom Classic 等の参照切れ対策は以下で行う。
- ファイル・フォルダ単位の Pin（自動階層移動対象外）
- 日付別ディレクトリ構造（`YYYY/YYYY_MM_DD/` 等）の維持
- 物理移動履歴（`file_move_history`）の記録
- `.xmp` 等のサイドカーファイルの追従管理

## 代替案
1. **WinFsp / Dokan による仮想ドライブ**: 物理移動を外部アプリから隠蔽できるが、カーネルドライバ依存・Windows アップデート追従・OS 固有障害・高 I/O 負荷時のデバッグ難度・macOS 移植コストが極めて大きい。

## 理由
- 個人開発 OSS において、仮想 FS 層の保守・障害切り分けコストはコアの写真資産保護・高速管理の品質を圧迫する。
- Pin と移動履歴・日付構造維持で、実用上の問題の大部分を安全かつシンプルに解決できる。

## 影響
- 外部アプリからは標準のローカル/UNC ファイルとして扱えるため、OS 依存障害やドライバ導入の手間を回避できる。
