# ADR-0007: Security by Design と Core 不変条件（Fail Closed）

- Status: Accepted
- Date: 2026-11-25

## 背景
WING PhotoVault は個人利用を主とするが、数十TBの代替不可能な写真資産を扱い、外部ファイル（カメラ・SDカード・ダウンロード画像・XMP）・外部カタログ・家庭内 LAN（NAS / 将来のリモート通信）と接する。バグや悪意ある入力によるデータ消失・任意コマンド実行・権限逸脱を初期設計から防ぐ必要がある。

## 決定
具体的な通信機能は後続フェーズで実装しつつ、信頼境界・入力検証・Core 不変条件を初期設計から組み込む。
- **Fail Closed**: 権限や状態が不明な場合は変更・削除を拒否する。
- **Core 一元強制**: 管理範囲外や `read_only` / `external` バックアップの変更禁止、コピー先検証前の削除禁止、オフライン≠消失を Core で強制する。
- **入力検証の徹底**: SQL はパラメータバインディング、外部コマンドはシェルを介さない引数配列＋オプション注入対策（`--`）、パスはルート境界とリンク/reparse point を検証、画像/EXIF/XMP/カタログ入力にはサイズ・ループ上限を設ける。
- **ネットワーク待受**: デフォルト無効。将来有効化する場合も登録済みホストのみ許可し、初期は参照系に限定する（TLS / 認証方式は実装前に確定）。独自暗号は実装しない。
- **最小権限**: 管理者 / root 権限を原則不要とする。

## 代替案
1. **個人用ツールとしてセキュリティ対策を後回しにする**: 後から境界検証や Fail Closed を全面改修するのは高コストであり、誤操作・不正ファイルによる資産消失リスクも高まる。

## 理由
- 安全性の不変条件はセキュリティだけでなく「写真資産を失わない」という中核要件そのものと一致する。

## 影響
- 外部アプリ起動・ExifTool 呼び出し・パーサ・インポート処理のすべてで境界チェックとテストを継続的に維持する。
