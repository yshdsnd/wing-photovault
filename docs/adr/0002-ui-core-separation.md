# ADR-0002: WING-UI と WING-Core / WING-CLI の分離

- Status: Accepted
- Date: 2026-11-25

## 背景
写真資産管理では、対話的な閲覧・連写選別（GUI）と、大量取り込み・定期スキャン・バックアップ・検索自動化（CLI / タスクスケジューラ）の両方が必要となる。また WING-UI のフレームワーク選定（Qt/QML, PySide6, Tauri, egui, Slint 等）は現時点で未確定であり、将来の変更可能性も残したい。

## 決定
管理処理・DB 更新・安全不変条件の強制をすべて **WING-Core / WING-CLI（`wingpv`）** に集約し、**WING-UI** は SQLite DB を直接更新せず、構造化出力（JSON / JSONL）を持つ CLI インターフェース（将来はライブラリ直結・IPC も検討）を介して連携する。

## 代替案
1. **GUI アプリ一体型（UI 層から直接 DB・FS を操作）**: 初期開発は早いが、定期実行や NAS ローカルスキャンが困難になり、UI 変更がコアの安全性に波及する。

## 理由
- Phase 1 から CLI 単体で実用化（スキャン・検索・統計・ベンチマーク）できる。
- UI フレームワークの選定を遅らせたり、後から差し替えたりしてもコア資産が無駄にならない。
- GUI / CLI / 将来 API に共通の不変条件（Read Only 保護・Fail Closed 等）を Core 1箇所で強制できる。

## 影響
- CLI の JSON / JSONL 出力形式・終了コード・エラー形式を安定した契約として維持する必要がある。
