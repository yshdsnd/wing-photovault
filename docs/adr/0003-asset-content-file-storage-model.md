# ADR-0003: 論理資産・内容・物理ファイル・ストレージの分離

- Status: Accepted
- Date: 2026-11-25

## 背景
実際の写真運用では、1回のシャッターで RAW（CR3）と JPEG の2ファイルが生成され、さらに複数の NVMe SSD・HDD・NAS に複製や移動が行われる。また NAS 上の過去データはローカルとフォルダ構造が異なる（`YYYY/MM_DD` や `RAW/`・`JPEG/` 分割など）。

## 決定
データモデルを **Asset（論理写真）→ Content（ハッシュ単位の内容）→ File（物理ファイル）→ Storage（保存先）** の4層に分離する。

## 代替案
1. **物理パスを主キーとする単純な1テーブル構成**: 階層移動（SSD→HDD）で評価・タグが切れやすく、NAS の旧フォルダ構造とバックアップ突合ができず、RAW+JPEG・バックアップ複製で撮影枚数が二重計上される。

## 理由
- フォルダ構造が異なっても Content（ハッシュ）一致で NAS バックアップ済みを正確に判定できる。
- 物理移動や故障からの復元を行っても Asset ID・評価・タグ・連写グループを維持できる。
- 論理写真単位と物理ファイル単位の両方で正確な統計が出せる。

## 影響
- DB スキーマと結合クエリはやや複雑になるが、適切なインデックスとバッチ登録により性能を担保する。
