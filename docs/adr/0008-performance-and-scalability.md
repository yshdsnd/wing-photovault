# ADR-0008: 3つの性能軸・パイプライン・有界キュー・計測駆動

- Status: Accepted
- Date: 2026-11-25

## 背景
航空機・野鳥撮影では1回で数千〜数万枚、累計で数十万〜数百万ファイルを扱う。単にバッチ処理が速いだけでなく、日常の検索・閲覧・選別で規模を意識させない応答性と体感速度が求められる。

## 決定
性能を以下の **3つの軸** で設計・評価し、複雑な最適化は必ず実測に基づいて採用する。
1. **実性能**: 物理デバイス種別（NVMe / HDD / NAS）ごとの並列度制御、差分スキャン、ストリーミングハッシュ（BLAKE3 / SHA-256 を実測比較）、ネイティブ EXIF 解析。
2. **応答性能**: CPU と I/O の分離、有界キューとバックプレッシャー、キャンセル、優先度制御（ユーザー選択画像 ＞ 画面内サムネイル ＞ 先読み ＞ 背景処理）。
3. **体感性能**: 逐次表示・パイプライン化・キーセットページング・RAW 埋め込みプレビュー・仮想スクロール・起動時全件検証の回避。

1万〜300万（必要に応じ1000万）ファイル規模でのダミー DB ベンチマークと、実ファイル I/O ベンチマークを分けて評価する。

## 代替案
1. **全件メモリロード・単純な一括処理**: 小規模では単純だが、100万ファイル規模でメモリ枯渇や長時間フリーズを引き起こす。
2. **測定なしの早すぎる最適化**: 複雑なロックフリー構造や耐障害性を損なう SQLite 設定（`synchronous=OFF` 等）は保守性と安全性を損なう。

## 理由
- 計測可能なベンチマーク（`wingpv benchmark`）を Phase 1 から持つことで、ボトルネックを実測で特定しながら段階的に高速化できる。

## 影響
- Phase 1 の初期実装（一括 `Vec` 走査等）も、大規模データでの計測結果を踏まえて有界キューによるストリーミングパイプラインへ段階的に移行する。
